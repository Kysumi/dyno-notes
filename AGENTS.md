# UI implementation rules

- Use shadcn/ui for every available UI primitive. Compose those primitives with
  semantic React layout elements; do not recreate buttons, inputs, cards,
  badges, checkboxes, separators, scroll areas, tooltips, dialogs, or similar
  controls.
- Add or update shadcn primitives with
  `deno run -A npm:shadcn@latest add <component>`. Never handwrite, copy, or
  reconstruct files in `src/components/ui`.
- Build pages from small, reusable React components in `src/components`. Keep
  component definitions at module scope and pass data through props.
- Style application code only with Tailwind utility classes in `className`.
- Do not add inline `style` props, CSS modules, CSS-in-JS, styled components, or
  handwritten CSS selectors and declarations.
- Keep `src/index.css` limited to the Tailwind import and theme/base tokens
  generated by the shadcn CLI. Do not add application-specific CSS there.
- Reuse an existing component before creating another component or adding a
  dependency.
